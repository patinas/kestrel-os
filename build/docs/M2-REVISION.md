# M2 revision notes
Fixes vs first draft: installer is VM-only (vd*/loop/QEMU model guard, refuses running disk, mounted disks, needs KESTREL_ALLOW_VM_INSTALL=yes and KESTREL_CONFIRM='ERASE <dev>'); builds the root tree once, applies the Kestrel overlay and user, populates BOTH slots; root ro via cmdline only, /var and /home on writable kdata; kernel+initramfs per slot on the ESP (/A, /B). Updater requires a minisign-verified image, derives the active slot from cmdline + mounted label, checks slots and ESP are on the same VM disk, writes by verified device path, cleans up on failure, arms 3-try boot. GPU selector runs as a root systemd oneshot. kestrel-mode uses two exact-name pkill calls.
Still untested; test only on a blank QEMU disk. Needs systemd-bless-boot wiring (kestrel-health.target) from docs/UPDATES.md before the 3-try fallback is real. Update.sh arms the new slot as default - a failed first-boot fallback depends on that wiring.

Execution guard: scripts require a QEMU guest and a virtio disk serial KESTREL_TEST_ONLY. Do not run them on a host or ordinary VM disk. Source is experimental and not yet install/update tested. No automatic rollback claim is valid until health/bless integration and reboot tests pass.

## Revision 3 (health gate, boot assessment, sizing)
- Installer: reads the authoritative installed package list (profile/airootfs/usr/share/kestrel/packages.installed.txt, generated by scripts/gen-installed-packages.sh = packages.x86_64 minus packages.live-only.txt; use --check in CI), installs it in ONE pacstrap transaction with the live pacman.conf after verifying [multilib] and `SigLevel = Required`. Copies usr/local/lib/kestrel, enables kestrel-health.service, rewrites the footer to "Kestrel OS alpha · installed", installs `kestrel-update`, and optionally a TEST-ONLY minisign pubkey (KESTREL_UPDATE_PUB, marked by /etc/kestrel/update.pub.TESTONLY).
- Sizing: roots 12 GiB (KESTREL_ROOT_GIB), ESP 512 MiB, needs disk >= 2*root+5 GiB; fails if the installed root passes 85% usage.
- Health gate: kestrel-health.service is RequiredBy/Before boot-complete.target, so systemd-bless-boot only runs after it passes: compositor (cage/gamescope) and client (chromium/steam) exist and the SAME pid+start-time survive 60 s, root is mounted ro, local shell page readable. No external internet check. Fault injection: kernel arg `kestrel.test_crash_shell=1` kills the browser 15 s in; the gate fails and the entry stays unblessed.
- Boot assessment per systemd.io/AUTOMATIC_BOOT_ASSESSMENT: entries have sort-key + version, loader.conf `default kestrel-*`. Updater removes the target slot's entries before writing it, never touches the known-good entry, then adds `kestrel-X+3.conf` with a higher version. No EFI default variable is used, so persistent OVMF_VARS only matters for sd-boot's own boot-count variables. Refuses when the running slot has no counter-less (known-good) entry.
- Test helpers: scripts/make-test-keys.sh (host) and make-test-update.sh (inside the installed VM, packs running slot + staged kernel and signs).
Test status is recorded in ../../docs/TESTING.md. Installed A and rescue-repaired B health/blessing passed; the full corrected update path and rollback remain unverified. A future rollback test must use the actual known-good running slot as fallback, not assume its letter. VM load is prohibited on the shared TV host after two playback timeouts. Remaining fixes are source-only.
